Extract the technical skills from a resume's three sources below and return them as JSON, one list per source.

The input has three blocks, each starting with a marker line:
===SKILLS SECTION===  a cleaned, lowercase list of skills (layout may be messy)
===WORK EXPERIENCE=== prose describing jobs
===PROJECTS===        prose describing projects
A block may say "(none)".

Return ONLY this JSON object, with all lowercase strings and no explanation:
{"skills_section": [...], "work_experience": [...], "projects": [...]}
Use [] for a source with no skills.

WHAT COUNTS AS A SKILL
Programming languages, frameworks, libraries, databases, cloud services, tools, platforms, protocols, and named techniques or concepts (for example "rest apis", "embeddings", "ci/cd"). Never include soft skills, job titles, company names, project names, metrics, verbs, or generic engineering words that name no specific technology or technique (for example "dashboards", "security", "performance", "scalability").

RULES
1. Copy each skill as written, lowercased. Never add, infer, rename, expand, shorten or spell-correct a skill. If the text says "postgres", output "postgres". Only extract skills that are explicitly named.
2. SKILLS SECTION: skip category labels ("languages", "cloud & devops"). Split on commas, pipes, line breaks, or spaces, but keep well-known multi-word names together ("apache flink", "vector databases"). Join wrapped lines ("zero-trust" then "networking" is "zero-trust networking"). Split "a & b" into two skills. Keep slash names whole ("tcp/ip").
3. WORK EXPERIENCE and PROJECTS: pick out every named technology, tool and concept in the sentences, including ones in comma-separated lists or in parentheses. Ignore everything else.
4. Keep a bare entry even when longer variants sit beside it ("oci", "oci vault" and "oci functions" are three skills). Entries with extra words are different skills, not duplicates ("domain-driven design" and "domain-driven design ddd").
5. Each source is independent. Extract every skill named in that block, even if the same skill also appears in another block. Never take a skill from a block other than the one you are reading. No duplicates within a source. Keep order of first appearance.

EXAMPLE
INPUT:
===SKILLS SECTION===
languages
python, go
cloud & devops
aws, docker
===WORK EXPERIENCE===
Built REST APIs in Python, deployed to AWS with Docker and Kubernetes. Mentored 3 juniors. Cut costs 40%.
===PROJECTS===
Resume Matcher: FastAPI, Docker, Kafka. Ranked applicants using embeddings.
OUTPUT:
{"skills_section":["python","go","aws","docker"],"work_experience":["rest apis","python","aws","docker","kubernetes"],"projects":["fastapi","docker","kafka","embeddings"]}
